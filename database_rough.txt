2. tbl_oauth_accounts
Links a Google or GitHub login to a tbl_users account, so the same person can sign in with either provider or with a password.
Column
Type
Description
oauth_account_id
UUID (PK)
OAuth link ID
oauth_account_user_id
UUID (FK -> tbl_users.user_id)
Owning user account
oauth_account_provider
ENUM
google, github
oauth_account_provider_user_id
VARCHAR
Unique ID returned by the provider
oauth_account_created_at
TIMESTAMP
When this login method was linked

Unique constraint
(oauth_account_provider, oauth_account_provider_user_id) - the same provider account can never be linked to two different users

3. tbl_refresh_tokens
Recommended addition for JWT-based auth. Access tokens stay short-lived and stateless; refresh tokens are stored so they can be revoked (e.g. on logout or password change).
Column
Type
Description

Token row ID
refresh_token_user_id
UUID (FK -> tbl_users.user_id)
Owning user
refresh_token_hash
TEXT
Hashed refresh token (never store it raw)
refresh_token_expires_at
TIMESTAMP
Expiry time
refresh_token_revoked_at
TIMESTAMP, NULLABLE
Set when the token is revoked before expiry
refresh_token_created_at
TIMESTAMP
Created time

Future Improvement
For long-term scalability, consider adding a tbl_workspace_roles table (or a permissions-override table) if different permissions are ever needed within different workspaces - for example, a teacher who is an "Instructor" in one workspace but only a "Teaching Assistant" in another.
If that flexibility isn't needed yet, the current organization-level roles plus workspace membership are sufficient, and keep the design simpler.
